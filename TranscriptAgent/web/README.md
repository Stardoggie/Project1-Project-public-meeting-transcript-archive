# Web front end

One page, `index.html`, where the public asks questions about the archive's meetings and reads or downloads full
transcripts. It talks only to the **read-only chatbot** (`app/chatbot`), which can't add, change or delete anything.

When it opens, it shows the three most recent meetings (dated today or earlier, newest first) in a column to the
right of the chat, or in a strip above it that scrolls sideways on narrow screens. Each has buttons that ask the
chatbot to summarize it or show its transcript. The page gets them from `POST /api/recent`, which sends
the chatbot `{"recent_meetings": 3}`; the chatbot looks them up in the archive without the model.
Managing meetings and uploading recordings is done with the admin agent from the terminal chat (`../cli`).

It runs in two ways.

## Hosted (CloudFront)
`agentcore deploy` publishes it. The stack outputs `SiteUrl` (the CloudFront address).

- **No sign-in:** anyone with the address can ask questions. Answers come only from the archive, over database
  connections that can only read.
- **API:** CloudFront sends `/api/*` to a Lambda (`agentcore/cdk/lambda/api/index.ts`) through origin access control.
  The Lambda sends each question to the chatbot runtime. Each conversation is kept apart by its session id, a random
  value the browser makes.
- `config.json` (which tells the page it's hosted) is generated by the deploy. It isn't in this folder.

## Local
Start the chatbot in `TranscriptAgent/`, on port 8090 so the terminal chat (which looks on 8080-8089) never finds it
by mistake:
```
agentcore dev --agent chatbot --port 8090
```
Then, in this folder:
```
python server.py
```
and open http://127.0.0.1:8501. The server only listens on this computer.

To use the deployed chatbot with your own AWS credentials instead:
```
uv run --project ../app/chatbot python server.py --deployed
```
(`--runtime-arn <ARN>` picks a runtime explicitly; `agentcore status` lists them.)
