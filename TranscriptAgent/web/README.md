# Web front end

One page, `index.html`, for chatting with the agent, answering its confirmations, uploading MP3/WAV recordings and
reading or downloading full transcripts. It runs in two ways.

## Hosted (CloudFront)
`agentcore deploy` publishes it. The stack outputs `SiteUrl` (the CloudFront address) and `UserPoolId`.

- **Sign-in:** Cognito, with its hosted login page. Nobody can sign up on their own; add each user with:
  ```
  aws cognito-idp admin-create-user --user-pool-id <UserPoolId> --username clerk@example.org --user-attributes Name=email,Value=clerk@example.org Name=email_verified,Value=true
  ```
  Cognito emails them a temporary password, which they change at first sign-in.
- **API:** CloudFront sends `/api/*` to a Lambda (`agentcore/cdk/lambda/api/index.ts`) through origin access control. The Lambda
  checks the user's access token and calls the runtime with the user's Cognito id as `actorId`. The runtime session
  is tied to that user too, so nobody can read or answer someone else's conversation.
- **Uploads** go from the browser straight to the presigned S3 link the agent hands out. The recordings bucket
  allows `PUT` from the site's address only.
- `config.json` (the login address and client id) is generated by the deploy. It isn't in this folder.

## Local
With `agentcore dev` running in `TranscriptAgent/`:
```
python server.py
```
Then open http://127.0.0.1:8501. There's no sign-in: the server only listens on this computer, and it uploads
recordings for the page. To use the deployed runtime with your own AWS credentials instead, run
`uv run --project ../app/agent python server.py --runtime-arn <runtime ARN>` (`agentcore status` shows the ARN).
