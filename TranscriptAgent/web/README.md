# Web front end

One page, `index.html`, where the public can ask about governing bodies, meetings and transcripts, and read or
download full transcripts. It talks only to the read-only `public_agent` runtime (`app/agent/public_main.py`), which
can't add, change or delete anything. Clerks manage meetings and recordings with the terminal chat (`../cli/`). The
page runs in two ways.

## Hosted (CloudFront)
`agentcore deploy` publishes it. The stack outputs `SiteUrl` (the CloudFront address).

- **No sign-in**, since the agent behind it can only read the archive.
- **API:** CloudFront sends `/api/*` to a Lambda (`agentcore/cdk/lambda/api/index.ts`) through origin access control.
  The Lambda calls `public_agent` and nothing else. Each conversation is kept apart by its session id, a random value
  the browser makes.
- `config.json` (which tells the page it's hosted) is generated by the deploy. It isn't in this folder.

## Local
Start the public agent in `TranscriptAgent/` (port 8090 keeps it apart from the clerks' agent on 8080):
```
agentcore dev --agent public_agent --port 8090
```
then, in this folder:
```
python server.py
```
Then open http://127.0.0.1:8501. The server only listens on this computer. To use the deployed `public_agent` with
your own AWS credentials instead, run `uv run --project ../app/agent python server.py --runtime-arn <its ARN>`
(`agentcore status` shows it).
